# Nota de trabajo — 22 de agosto 2026

## Arreglo de hoy: el bloqueo del teléfono físico

**Problema.** El default del broker era `http://127.0.0.1:8787` (iOS) / `10.0.2.2` (Android) en
`src/services/brokerApi.ts`. Funciona en simulador (comparte la red de la Mac), pero en un
teléfono físico `127.0.0.1` es el propio teléfono y `10.0.2.2` solo existe en el emulador.
Toda llamada al broker (sesión, alta de identidad, pruebas) fallaba con errores de conexión
que parecían "broker caído".

**Cambios hechos** (typecheck, lint y 77 tests limpios tras el cambio):

1. **`.env.local`** (nuevo, gitignored) — apunta el broker a la Mac:
   ```
   EXPO_PUBLIC_M8_BROKER_URL=http://192.168.0.4:8787
   ```
   ⚠️ Esa IP es la de hoy. Si la Mac cambia de red, actualizarla ahí
   (`ipconfig getifaddr en0`). Expo la carga solo al iniciar `expo start`.

2. **`src/services/brokerApi.ts`** — `getBrokerBaseUrl()` ahora avisa en desarrollo si no hay
   variable configurada, explicando que el default solo sirve en simulador.

3. **`app.json`** — añadido `NSAppTransportSecurity → NSAllowsLocalNetworking` en el
   infoPlist de iOS, para que un dev build pueda hablar HTTP plano con la IP LAN (Expo Go
   ya lo permitía; el dev client no).

**Para probar en el teléfono:**
- El broker debe estar corriendo en la Mac (puerto 8787) — hoy no había nada escuchando.
- Teléfono y Mac en la misma red Wi-Fi.
- Reiniciar el server de Metro tras cambiar `.env.local`.
